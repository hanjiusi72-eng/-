# 纹样之声 · Pattern Instrument

网页端交互作品。以用户提供的动态纹样为画面来源，食指选择位置，拇指与食指捏合弹奏；也可用鼠标、拖动、触屏或键盘参与。

## 启动

需要 Node.js 20 或以上。无需 npm 安装、账号、API Key 或运行时网络请求。

```sh
cd /workspace/-
npm start
```

解压下载包后，在项目目录运行 `npm start` 即可。页面底部可直接观看创作短片。

服务默认端口 3000，可通过 `PORT` 更改。在本机浏览器访问此服务；远程部署需使用 HTTPS 才能申请摄像头权限。不要直接用文件协议打开 HTML。

1. 开启声音，或直接点击画布。之后声音开关可以静音；源视频始终静音。
2. 鼠标点击、按住跨单元拖动、手机触屏均可发声。键盘聚焦画布后，方向键选择、空格或回车触发。
3. 手势体验先开启摄像头取景，再单独启动识别。取景是镜像，食指坐标映射到整个纹样画布。伸出食指，用拇指靠近食指捏合，松开后再次触发。
4. 同一次捏合只发声一次；掌长归一化阈值、双阈值滞回与 220 ms 冷却避免抖动。
5. 分区、音量、暂停、播放速度、粒子扩散、复原时间和全屏位于界面中。

## 画面与声音

- 16×8 个固定区域，骨式位置固定。原始持续律动素材中有文字、界面和预制手形光标，不能直接当作实时演奏画面。本版裁切纹样，以干净首帧建立固定结构，64 色量化后从原片各区域逐帧采样配色；末秒平滑回到首帧配色，形成循环。原片的结构与色彩变化被保留，但并非逐像素原视频直放。
- 触发时读取当前区域真实像素。饱和度加权的主色色相映射 C4、D4、E4、G4、A4；填色密度影响 0.8–4.3 秒延音，亮度影响泛音与低通滤波。音乐用 Web Audio 实时合成，无视频原声。
- 区域图像拆为粒子向外散开，默认 3 秒归位；最后阶段与正在播放的当前帧交叉融合，其他区域持续播放。动态暂停只暂停源视频，已经触发的粒子继续复原。
- MediaPipe Hands 0.4.1675469240 的运行库、WASM 与手部模型都在 `public/vendor/hands`，摄像头画面不上传、不录制。浏览器仍会要求摄像头权限。
- 摄像头取景与识别可以分别关闭；识别启动或推理失败时保留取景与鼠标/触屏功能，并显示原因。
- `Ripple_Flow_Compatible.mp4` 与艺术短片保存在 `public/media` 作为原始参考；默认演奏画面使用固定几何的持续律动版本。

## 验证

```sh
npm test
# 已启动服务后；Python Playwright 与 Chromium 可用时：
python3 tests/browser_smoke.py
```

4 个核心测试覆盖全部区域坐标、颜色映射、捏合防抖与粒子归位。13 项浏览器集成检查及 1 项手部素材回放验证覆盖静音视频、暂停、真实非零音频采样、粒子、拖奏、控制、手机触屏、本地识别模型加载与推理、识别失败保留取景。结果在 `deliverables/browser-validation.json`；手部回放结果在 `deliverables/validation.json`。

自动化摄像头测试使用模拟视频输入；另用附件中的手部片段进行了本地回放识别。真实摄像头、实际手的距离、光照及个人捏合习惯仍需现场体验确认。单目食指定位与捏合不等同真实桌面触碰；投影四角校准按需求留待后续，不包含在当前版本。

## 展示短片

- `deliverables/纹样之声_创作与交互短片.mp4`：56 秒，1920×1080，24 fps，H.264/AAC，原创立体声舒缓五声音阶配乐。
- `deliverables/纹样之声_原创配乐.wav`：独立 48 kHz 立体声配乐。
- 短片包含提供素材中的骨式生长、净化后的动态纹样、原型界面、网页实际鼠标演奏录屏与明确标注的手势流程示意。未把手势示意冒充为真实摄像头演奏实拍。
- `scripts/record_demo.py` 录制实际网页；`scripts/make_film.py` 生成字幕、流程图、原创音乐及成片。前者需要 Playwright/Chromium，后者需要 FFmpeg、Python NumPy、Pillow 与 Noto CJK 字体。
- 原始持续律动附件可用 `python3 scripts/prepare_pattern.py public/media/motion-study-source.mp4` 重新提取纹样。素材路径作为参数传入，不写死到启动流程。

## 项目结构

`public/` 为可部署的静态站点，`server.mjs` 为零依赖本地开发服务器；所有运行素材与模型均随项目保存。部署到支持 WASM、MP4 和 HTTPS 的静态服务器即可使用。

保留当前隔离环境的仓库，不需要创建额外 Git worktree。仓库起初没有提交，本次未推送或发布任何内容。

## GitHub Pages 发布

静态发布分支为 `gh-pages`，站点根目录为该分支 `/ (root)`。在仓库 Settings → Pages → Build and deployment 中选择 Deploy from a branch、gh-pages、/ (root)，保存。项目使用相对路径，可部署到仓库子路径。

更新流程：提交并推送 main 后执行 `bash scripts/deploy-pages.sh`，将 public 的已提交内容发布至 gh-pages，保留既有发布历史。不推送生成的影片中间文件或下载 ZIP。
